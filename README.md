# litany

Recurring task engine: due dates, no-due tasks, recurrence rules, completion
history, streaks. Part of the TechGodHQ fleet.

## Shape

- **Core** (`crates/litany-core`): pure domain logic — tasks, recurrence
  rules, occurrences. No HTTP, no Telegram, no UI.
- **Surfaces**: CLI/HTTP/MCP generated by [hydra](https://github.com/TechGodHQ/hydra)
  from `api/operations.yaml` (to land; see Linear project **Litany**).
- **Storage**: SQLite at `/data/litany.db` in the deployed container.

## Model

- `Task` — name, optional due date, optional recurrence (`daily`,
  `every N days`, `weekly [on weekday]`, `every N weeks`, `monthly [on day]`,
  `every N months`, `every N days from last completion`).
- `Occurrence` — one row per actual completion, with its real timestamp.
  Streaks and history are **derived** from occurrences; nothing stores a
  mutable counter that can drift from reality.

## Dogfood consumer

Litany is consumed over iris (Telegram) the way hermes-comms is: "done",
"what's due today", streak check-ins. No client UI is planned; the hydra
surfaces are the product.
